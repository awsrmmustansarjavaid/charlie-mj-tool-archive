# Charlie MJ Tool Archive v5.0.0 — Dual Library & Smart Synchronization

## Overview

Version 5.0.0 changes the library architecture from a single merged default source into two independent default resources:

- **🏠 Local Default Library** — the packaged `data/default-tools.json` shipped with the extension.
- **☁️ Remote GitHub Library** — `data/default-tools.json` read from the public GitHub repository.

The extension builds a unified dashboard from both sources without creating duplicate cards for the same normalized URL.

Repository:

`https://github.com/awsrmmustansarjavaid/charlie-mj-tool-archive`

Remote source:

`https://raw.githubusercontent.com/awsrmmustansarjavaid/charlie-mj-tool-archive/main/data/default-tools.json`

---

## 1. Dual Default Libraries

The extension keeps the two default resources independently.

```text
Local default-tools.json
        │
        ├───────────────┐
        │               │
        ↓               ↓
   Local Library    Unified View
                        ↑
        Remote Library │
        ↑               │
GitHub default-tools.json
```

### Local Default Library

The packaged JSON is available offline and acts as the extension's local default resource.

### Remote GitHub Library

The public GitHub JSON is downloaded and cached by the extension. It can be refreshed manually or automatically.

---

## 2. Source Badges

Every unified tool can display one of three source states:

### 🏠 LOCAL

The normalized website exists only in the local library.

### ☁️ REMOTE

The normalized website exists only in the GitHub remote library.

### 🏠 LOCAL + ☁️ REMOTE

The same normalized website exists in both libraries.

The source badge is shown on tool cards and in the details view.

---

## 3. Unified Deduplication

A website appearing in both libraries is shown once.

For example:

```text
Local:
https://example.com/

Remote:
https://www.example.com/?utm_source=archive
```

is normalized into one unified record when the normalized URL matches.

Meaningful paths remain distinct:

```text
https://example.com/tools
https://example.com/download
```

The archive removes query strings and fragments for duplicate comparison, while retaining the useful URL path.

## 7. GitHub Synchronization

The extension can synchronize the remote library:

- On extension startup.
- Through **Settings → Sync from GitHub Now**.
- Periodically using the Chrome alarms API while Chrome is active.
- According to the configured synchronization interval.

Available intervals include:

- 15 minutes
- 30 minutes
- 1 hour
- 6 hours
- Daily

Automatic synchronization can also be disabled.

---

## 8. Sync History

The extension keeps recent synchronization summaries containing:

- Time
- Status
- New remote tools
- Updated remote tools
- Remote tools removed from the current GitHub file

This is visible from Settings.

---

## 9. Remote Change Detection

When the remote JSON changes, the extension compares normalized records and reports:

- Added remote tools
- Updated remote tools
- Removed remote tools

The extension does not silently delete local records because a tool disappeared from GitHub.

---

## 10. Remote Deletion Protection

GitHub removal is never treated as permission to delete a local personal record.

If a remote-only record disappears from GitHub, it disappears from the current remote cache, but an existing local copy remains available.

This protects personal data from accidental remote deletion.

---

## 11. Remote-Only Tools and Local Copies

A remote-only tool can be opened normally.

If the user wants to edit, favorite, add notes or otherwise customize it, the extension provides **Create Local Copy**.

After creating a local copy, the same URL is represented as:

```text
🏠 LOCAL + ☁️ REMOTE
```

The local record can then contain personal metadata without changing GitHub.

---

## 12. Local Overrides

Local metadata is treated as personal information.

Favorites, notes, usage information and local edits are not blindly overwritten by a remote synchronization.

Remote data can still provide useful default information when local fields are missing.

---

## 13. GitHub-Ready Export

Settings includes **Prepare GitHub Update**.

This generates a clean `default-tools.json` suitable for publishing as the repository's default library.

Personal runtime fields such as:

- favorite state
- personal notes
- usage timestamps
- usage counters
- local source metadata

are excluded from the GitHub default snapshot.

Recommended workflow:

```text
Add/edit locally
      ↓
Prepare GitHub Update
      ↓
default-tools.json
      ↓
Commit to GitHub
      ↓
Remote Library
      ↓
Other installations can synchronize
```

## 21. Data Storage Model

The v5 data model uses separate storage areas:

```text
chrome.storage.local
│
├── localLibrary
├── remoteLibrary
├── settings
├── syncState
├── syncHistory
└── syncChanges
```

The dashboard then derives:

```text
localLibrary + remoteLibrary
             ↓
       URL matching
             ↓
       Unified Library
```

This avoids treating the unified dashboard as the permanent source of truth.

---

## 22. Important Data Safety Rule

The extension follows this principle:

> Remote GitHub data is a shared/default resource. Local data is personal.

Therefore synchronization should prefer additive and non-destructive behavior.

---

## 23. Installation

1. Extract the repository.
2. Open `chrome://extensions/` in Chrome.
3. Enable **Developer mode**.
4. Select **Load unpacked**.
5. Choose the project directory containing `manifest.json`.
6. Open Charlie MJ Tool Archive.

After source changes, use **Reload** from the Chrome extensions page.

---

## 24. Recommended GitHub Workflow

For maintaining the public default library:

1. Add or edit tools locally.
2. Use **Prepare GitHub Update**.
3. Save the generated `default-tools.json` into the repository's `data/` directory.
4. Commit and push the change.
5. Other extension installations can discover the updated remote library during synchronization.
